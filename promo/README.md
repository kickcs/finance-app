# Промо-ролик Ouro Finance

1920×1080, 30 fps, ровно 84.0 с, со звуком. Реальные экраны приложения +
анимированные оверлеи Remotion. Дизайн: `docs/superpowers/specs/2026-08-10-promo-video-16x9-design.md`.

## Порядок сборки

```bash
# 1. Стенд. Отдельный vite нужен потому, что VITE_API_URL в frontend/.env
#    указывает на LAN-адрес машины — по нему бэкенд отсюда недоступен.
docker compose up -d postgres
cd backend  && bun run start:dev
cd frontend && VITE_API_URL=http://localhost:3000 bunx vite --port 5199

# 2. Данные и экраны. capture сам логинится демо-кнопкой и сам зовёт seed.
cd promo
npm run capture                       # русские экраны  → public/shots/
node scripts/capture.mjs --lang=en    # английские      → public/shots/en/

# 3. Звук
npm run audio

# 4. Рендер с мастерингом — обе языковые версии
npm run render          # → out/promo-16x9.mp4
npm run render:en       # → out/promo-16x9-en.mp4

npx remotion studio --no-open   # предпросмотр и правка мышкой
```

`npm run seed` отдельно — только для отладки сида: он тогда логинится сам и
создаёт своего демо-пользователя, не того, который будет сниматься.

## Две языковые версии

Композиции `Promo` и `PromoEn` — один и тот же компонент с разным пропом `lang`.
Общий монтаж, тайминг, звук; различаются только подписи из `src/copy.ts`.
Сцены берут копию через `useCopy()`, дефолт контекста — русский, поэтому
предпросмотр отдельной сцены в Studio остаётся русским.

Раскладка у версий общая, поэтому английская строка обязана влезать в тот же
бокс. Заголовок в 72 px выровнен по нижнему краю блока: лишняя строка не
обрезается, а поднимает первую вверх, в кадр. Проверять до рендера:

```bash
npm run measure         # Inter в настоящем Chrome, каждая строка против бокса
npm run measure -- --all
```

## Английские экраны

Английская версия снимается с того же стенда, тремя слоями — и порядок здесь
важнее самих слоёв:

1. **Данные.** Демо-юзер создаётся русским (`POST /auth/login/anonymous` языка
   не принимает, а `DemoInitializationService` читает его из профиля), поэтому
   `seed.mjs` после создания переписывает категории, счета, людей и описания
   операций — парами из `backend/src/i18n/{ru,en}/*.json`, то есть
   формулировками самого бэкенда, — и ставит `language: en` в профиль.
2. **Фронт.** Браузер стартует с `locale=en` в localStorage: даты, числа и уже
   переведённые слайсы приложение отдаёт само.
3. **Словарь.** `scripts/shot-strings.json` подменяет в DOM то, что во фронте
   пока захардкожено по-русски. Список собран прогоном, а не по памяти:
   `node scripts/capture.mjs --lang=en --harvest` пишет все видимые кириллические
   строки в `scripts/harvest.json`.

Чем больше берут на себя первые два слоя, тем меньше словарь: подмена в DOM
показывает состояние, которого приложение ещё не отдаёт, и держать её нужно на
минимуме. После раскатки i18n словарь сокращается до пустого, а шоты
переснимаются той же командой.

Правила словаря не идемпотентны («27 776 253» → «27,776,253»), а запись в
`nodeValue` будит MutationObserver — поэтому переводчик помнит свой результат и
второй раз строку не трогает.

Пробел в шаблоне правила означает «любой пробел» и разворачивается до
компиляции: `Intl` в русской локали ставит между разрядами NBSP, а не обычный
пробел. По той же причине сокращения съедают пробел перед собой
(`\s?млн` → `M`): по-русски пишут «2,31 млн», по-английски — «2.31M».

Координат в сценах нет: английские подписи другой длины, и чипы, строки чека и
участники встают иначе. Сцены читают рамки из `public/shots/**/boxes.json`
через `useShots()` — того же файла, который пишет `capture`. Переснял — сцены
поехали за экраном сами.

## Что в ролике

Порядок — один день из жизни, а не оглавление функций: пришло уведомление
банка → импорт → наличные → ужин → делёж → долги → история → аналитика →
бюджет → «и на компьютере».

| # | Сцена | Слот | Экран | Такты оверлеев |
|---|---|---|---|---|
| 1 | Утро | 180 | — | карточка уведомления HUMO, строка, уезд вправо |
| 2 | Импорт | 324 | `/import-inbox` → подтверждение | три карточки → смена экрана → разобранный блок |
| 3 | Быстрый ввод | 216 | `/transactions/new` | сумма → чип категории → делёж и скан |
| 4 | Чек | 252 | визард, «Позиции» | сканер → три позиции → итог |
| 5 | Делёж | 252 | визард, «Участники» | способ дележа → «6 из 6» → строки позиций |
| 6 | Долги | 252 | `/debts` | должен вам → вы должны → нетто |
| 7 | История | 216 | `/history` | фильтры → две линейки дня |
| 8 | Аналитика | 252 | `/analytics` | график темпа → кольцо → список категорий |
| 9 | Бюджет | 216 | `/` дашборд | карточка баланса → «сколько в день» |
| 10 | Везде | 216 | десктопный дашборд | четыре строки перечня |
| 11 | CTA | 144 | — | логотип, домен, «демо без регистрации» |

Слоты дают 2520 кадров. В коде у каждой сцены, кроме последней, стоит +18 кадров
на перекрытие перехода, поэтому сумма `durationInFrames` = 2700, а итог
2700 − 10 × 18 = **2520 кадров = 84.0 с**. Менять длину сцены — значит
пересчитать эту сумму, иначе ролик перестанет попадать в целое число тактов.
Проверка: `npx remotion compositions` показывает у `Promo` ровно 2520.

Абсолютные старты сцен — 0, 180, 504, 720, 972, 1224, 1476, 1692, 1944, 2160,
2376. По ним расставлены SFX в `Promo.tsx`.

Темп 100 BPM: доля 18 кадров, такт 72. Все длительности кратны половине такта,
поэтому каждый рез приходится на долю — и подложка ложится на резы без подгонки.

## Кадр: телефон и лупа

Портретный экран целиком в кадре 16:9 нечитаем: по высоте помещается телефон
~910 px, и текст интерфейса 15 px превращается в **16 px**. Поэтому кадр
разделён:

- **телефон 380×824** слева отвечает за «где мы»;
- **лупа 1179×720** справа показывает тот же скриншот в родных пикселях DPR-3 —
  тот же текст читается как **45 px**. Увеличения интерполяцией нет вовсе,
  отсюда и отсутствие мыла.

Ширина лупы равна ширине источника, поэтому горизонтального панорамирования не
существует: лупа ездит только по вертикали, и анимируемая величина одна —
`loupeTop` в пикселях источника.

**Рамка-указатель** на телефоне показывает, какую полосу сейчас показывает лупа.
Её координаты производные: `0.32231` — это `380/1179`.

Кадр держится на двух вертикалях: **135** слева (знак, телефон) и **1784**
справа (правый край лупы и подписи). Подпись живёт над лупой и прижата к низу
своей колонки, поэтому заголовок в две строки растёт вверх и зазор до лупы
постоянный.

Единственное исключение — сцена «И на компьютере»: десктопный скриншот лежит
панелью 1440×810, подпись под ней в чистой полосе. Полный кадр во всю площадь
пробовали: подпись ложится поверх плотного интерфейса и не читается ни с
заслонкой, ни без неё, а наезд вдобавок срезает сайдбар.

## Движение

Хронометраж наращивается **удлинением пауз, а не замедлением анимаций**:
скорость входов, панорам и наездов — величина постоянная, менять её значит
получить вялое движение вместо спокойного. Растягиваются интервалы между тактами
и финальные выдержки.

Две кривые на весь ролик: вход — `Easing.bezier(0.22, 1, 0.36, 1)`, панорама и
наезд — `Easing.bezier(0.65, 0, 0.35, 1)`. `Easing.linear` только у медленных
дрейфов, у которых не должно быть ни начала, ни конца. Ничего не появляется
быстрее 12 кадров и не въезжает быстрее 20 — вход занимает примерно долю.

Посегментные easing'и обязательны: `interpolate()` принимает массив по одному
на сегмент, и четырёхключевая анимация «появился — держится — исчез» на одном
easing даёт рубленые вход и выход.

Объём — тремя слоями: Z-компонента `translate` при `perspective` на сцене
(отдельного `scale` поэтому нет, иначе наезд считался бы дважды), параллакс
подписи и телефона относительно лупы, дышащее пятно за корпусом плюс виньетка.
Разворот `rotate: "y -7deg"` не поддерживается — Remotion не интерполирует ось.

Панорама лупы всегда имеет паузу до и после: полоса должна успеть прочитаться,
прежде чем уедет. Проездов в сцене может быть два — в «Аналитике» лупа идёт с
графика темпа на кольцо, а затем на список категорий.

Движение обязано что-то сообщать. В «Аналитике» была заслонка, «дорисовывавшая»
кольцо поворотом на 360°: диаграмма уже нарисована в скриншоте, так что
заслонка закрывала настоящие данные, чтобы затем их открыть. Убрана, время
отдано второму проезду.

У сцены «Бюджет» панорамы как такта нет — карточка баланса и строка «расход/дн»
попадают в одну полосу лупы. Но после последней подсветки сцена держится ещё три
с половиной секунды, и неподвижный кадр за это время умирает: лупа ползёт на
46 px за всю сцену. Этого хватает, чтобы кадр оставался живым, и мало, чтобы это
читалось как отдельный такт.

Переходы — 18 кадров. Между экранами приложения **сдвиг**, а не наплыв: на
середине наплыва две плотные текстовые лупы накладываются и читаются кашей.
Наплыв остался там, где кадр почти пуст (вход из «Утра», выход в CTA), и там,
где раскладка меняется целиком (переход к десктопной сцене).

## Звук

Всё синтезируется `scripts/make-audio.mjs` на чистом Node, без зависимостей и
без вопросов о правах. Шум берётся из детерминированного генератора: одинаковый
запуск даёт побайтово одинаковый файл.

- `bed.wav` — подложка 100 BPM, ля минор, 35 тактов = ровно 84.0 с. Границы
  ярусов заданы константами `DRUMS_IN` / `DRUMS_OUT` / `PLUCK_IN` /
  `SIXTEENTHS_FROM` / `PAD_CLOSE_FROM` в тактах и привязаны к монтажу: ударные
  входят сразу после «Утра» и уходят на десктопной сцене, поэтому ролик
  начинается в тишине и в ней же заканчивается. При смене длины правятся
  только эти константы и `BARS`.
- `sfx-whoosh` — на каждом из десяти резов, тихо (0.25): свуш подчёркивает рез,
  а не объявляет его, `sfx-tick` — когда подсветка встаёт
  на элемент, `sfx-thock` — тап, `sfx-chime` — нетто-цифра и финал.

Позиции SFX заданы абсолютными кадрами в `Promo.tsx`, а не внутри сцен: сцены
внутри `TransitionSeries` имеют собственные таймлайны, и правка длительности
любой сцены заставляла бы пересчитывать всё.

`npm run render` после рендера прогоняет мастеринг `loudnorm=I=-16` — YouTube
нормализует к −14 LUFS, и отдавать заметно тише смысла нет.

**Ролик обязан читаться без звука**: SFX ничего не сообщают, они лишь
подчёркивают то, что уже видно. Лендинг проигрывает без звука.

Если подложка на слух окажется лишней — снять `<Audio name="Bed">` в
`Promo.tsx`; SFX лежат отдельными файлами именно для этого.

`Audio` импортируется из `@remotion/media`: одноимённый компонент в ядре
`remotion` помечен устаревшим. `<Audio>` с несуществующим файлом валит рендер —
если Studio упал на старте, значит не отработал `npm run audio`.

## Кодирование

Настройки живут в `remotion.config.ts` и выбраны не по умолчанию:

- **`setVideoImageFormat("png")`.** Кадры отдаются энкодеру без JPEG-промежутка.
  Ролик тёмный, с золотом на почти чёрном: JPEG давал ореолы вокруг цветных цифр
  и блочность в тенях. PNG медленнее, но платим один раз при рендере.
- **`setCrf(15)` и `setX264Preset("slow")`.** На дефолтном CRF 18 тёмные
  градиенты рассыпались блоками по всей площади.
- **`setPixelFormat("yuv420p")` и `setColorSpace("bt709")`.** Без них файл
  выходил с `yuvj420p` и матрицей `bt470bg` (PAL), и часть плееров разбирала
  цвета не той матрицей.

Как проверять, что качество не уехало, — увеличенный кроп с растяжкой уровней,
на нём блочность видно раньше, чем глазом:

```bash
ffmpeg -i out/promo-16x9.mp4 -vf "select='eq(n\,1404)',crop=520:360:40:100,\
eq=contrast=4.2:brightness=0.16,scale=1560:1080:flags=neighbor" -frames:v 1 /tmp/band.png
ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt,color_space -of default=nw=1 out/promo-16x9.mp4
```

Остаточная мягкость цветных краёв — это 4:2:0, и она принята: 4:4:4 не играется
в Safari, а ролик живёт на лендинге.

## Данные для съёмки

Снимаем с локального инстанса, а не с прод-демо: у демо-юзера на проде пуст
инбокс импорта, нет подписок и один валютный счёт — «весь функционал» из этого
не собирается.

`scripts/seed.mjs` не сеет базу с нуля: демо-режим сам создаёт счета, операции,
долги и людей. Скрипт дописывает недостающее — валютный счёт, подписки, месячный
бюджет и инбокс Telegram-импорта.

**Инбокс наполняется настоящим парсером** `HumoMessageParser` — тем же классом,
который работает в бою, — на настоящих текстах уведомлений HUMO. Запись кладётся
в таблицу напрямую, минуя grammY: `bot.init()` ходит в Telegram за `getMe`, и
без валидного токена модуль выключается, а вебхук отвечает 503. Тянуть продовый
токен на машину разработчика нельзя — `onApplicationBootstrap` тем же заходом
переписал бы кнопку меню живого бота. Подменён только транспорт; разбор суммы,
магазина, карты и даты настоящий.

Сид запускается через `bun`: он импортирует парсер прямо из исходников бэкенда,
а bun читает TypeScript без сборки.

## Съёмка и замер

`scripts/capture.mjs` поднимает системный Chrome через `puppeteer-core`,
логинится демо-кнопкой, зовёт сид в ту же сессию (токен живёт 15 минут, а
refresh лежит в httpOnly-куке, которой у отдельного процесса нет), снимает
восемь мобильных экранов в 393×852 при DPR 3 и десктопный дашборд в 1280×720
при DPR 3, **и замеряет рамки тех элементов, которые подсвечивают оверлеи**.

Замер — не удобство, а необходимость: демо-сид у каждого прогона свой, и линейки
дней в истории уезжают на сотни пикселей. Подобранные на глаз координаты
переживали ровно один прогон.

Координаты печатаются **в пикселях источника** (CSS × DPR 3): оверлеи лежат
внутри слоя лупы, отрисованного один к одному со скриншотом, поэтому пересчёта
нет. Рядом печатается `loupeTop`, при котором элемент оказывается в середине
лупы.

Ищем элементы по видимому тексту, а не по CSS-селектору: классы у
Tailwind-разметки меняются от любой правки стилей, надписи живут дольше. Из
совпадений берётся самое внутреннее, дальше `climb` поднимает до нужной карточки.

Неочевидное, что там решено:

- **Гвард онбординга.** Первый заход на `/auth/login` уводит на `/welcome`, а без
  `onboardingComplete` любая страница уходит на `/onboarding/first-account`. Оба
  флага выставляются до навигации.
- **Ожидание логина — по токену, а не по пути.** Проверка «мы ушли с /auth» на
  `/welcome` истинна ещё до того, как демо-юзер создан.
- **Кнопка Vue DevTools удаляется из дерева**, а не гасится CSS: она живёт в
  кастомном элементе прямо в body. На проде её не было, на локальном стенде она
  вставала по центру снизу.
- **Аналитика снимается с прокруткой на 300 px**: без неё кольцо категорий стоит
  у самого низа и наполовину уходит под плавающую нижнюю навигацию.
- **Экраны чека берутся из засеянного черновика** `localStorage['scan-receipt:draft']`,
  а не из распознавания: фото в черновике всё равно не хранится, так что это
  законное состояние визарда, а не имитация OCR.
- **На шаге «Участники» сразу жмётся «Поровну на всех»** — иначе экран показывает
  «НАЗНАЧЕНО 0 ИЗ 6».
- **На экране новой транзакции печатается сумма** и тапается категория: пустая
  форма с «0 сўм» читается как «ничего не ввели».
- **Суммы сравниваются с нормализованными пробелами** — в вёрстке они неразрывные.
- **Даты в истории ищутся регуляркой**, иначе подстрока «7 августа» живёт сутки.
- **Версия ченджлога читается из исходников фронта.** Модалка «Что нового» гаснет
  только при точном совпадении версии.

## Если интерфейс изменился

Перезапустить `npm run capture` и перенести напечатанные рамки и `loupeTop` в
сцены. Если рамка села не на тот уровень вложенности — менять `climb` у
соответствующего `measure()`, а не подгонять числа руками.

В оверлеях чисел нет намеренно — они только обводят настоящие элементы, поэтому
пересъёмка их не ломает.

## Правки в Studio

Стили и кейфреймы написаны инлайн литералами, а заголовки не вынесены в общий
компонент — это сделано ради интерактивности: текст, размеры и тайминги правятся
в Studio мышкой и пишутся обратно в код. Не выносите цвета в константы, иначе
Studio перестанет их редактировать. По той же причине перспектива живёт на
родителе: `transform`-строку Studio уже не правит.

Одно осознанное отступление: `loupeTop` приходит в `Stage` пропом-числом,
поэтому панорама лупы правится только в коде. Альтернатива — повторить разметку
окна лупы в девяти сценах, и тогда геометрия неизбежно разъедется.

`"./src/fonts.ts"` обязан оставаться в `sideEffects` в `package.json`: иначе
бандлер выбросит импорт как безрезультатный и весь текст уедет на засечный
подменный шрифт.
