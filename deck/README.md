# deck — инвесторская презентация

Слайды 1920×1080 (16:9) на HTML, печатаются в PDF системным Chrome. Дизайн описан в
`docs/superpowers/specs/2026-08-10-investor-deck-pdf-design.md`.

```bash
bun install
bun run fonts      # один раз: скачать woff2 в public/fonts
bun run capture    # пересъёмка экранов прод-демо (нужен Chrome и интернет)
                   # OURO_HOST_IP=<ip> — если резолвер не знает домен прода
bun run pdf        # → out/ouro-finance-deck.pdf
bun run pdf:en     # → out/ouro-finance-deck-en.pdf
```

Два языка — два `src/index*.html` на общем `deck.css` и общих скриншотах. Правку содержания
надо вносить в оба файла: связи между ними нет, и расхождение сборка не поймает. `--png`
дополнительно кладёт каждый слайд картинкой в `out/preview/<имя дека>/` для быстрой сверки.

## Что важно знать, прежде чем править

**Никаких CSS-градиентов.** `radial-gradient` и `repeating-linear-gradient` Chrome не умеет
класть в PDF вектором — вместо этого он рисует картинкой всю страницу. Один пунктир под
надстрочником раздувал файл с 3,4 до 18 МБ. Перфорация и фестоны сделаны штрихом с круглыми
торцами внутри SVG (`stroke-dasharray: 0.1 15`, `stroke-linecap: round`) — тот же вид,
вектор в PDF. Скругления и повороты безопасны, тени — нет (ниже).

**Знак вне подмножества шрифта тянет системный шрифт.** Скачиваются только `cyrillic` и
`latin`, поэтому стрелки, длинные тире из других диапазонов и типографские редкости Chrome
нарисует Menlo и вошьёт его в PDF. Сборка это ловит: после печати она читает `/FontName` в
готовом файле и падает на любом шрифте вне Golos Text / IBM Plex Mono / Inter.

**Никаких теней.** Chrome не размывает `box-shadow` при печати, а рисует сплошную серую
плашку вокруг блока — в PDF под каждой карточкой встаёт прямоугольник. Слои разделены
белым по фарфору и рамкой `1px solid var(--line)`.

**`bun run pdf --png` печатает превью с готового PDF**, а не снимает страницу в браузере.
Снимок страницы врёт ровно там, где печать ведёт себя иначе, — тени в деке прожили целую
итерацию именно из-за этого. Сверять надо то, что увидит адресат.

**Английские кадры — подмена текста, а не английская сборка приложения.** Локализация
выкачена на 2 слайса из 80, снимать нечего. `capture.mjs` снимает каждый экран дважды: как есть
в `public/shots/`, затем подменяет текст в DOM по `scripts/shots-en.mjs` и снимает в
`public/shots/en/`. Оба кадра — из одной сессии, то есть у одного демо-юзера: иначе цифры в
русском и английском деке разойдутся. Английский дек оговаривает это подписью на слайде 4.

Категории, счета, контакты и подписи операций словарь берёт из `backend/src/i18n/{ru,en}/`
(там уже есть полный перевод демо-данных) — руками в `shots-en.mjs` дописан только хром
фронтенда. Строку, для которой не нашлось ни словаря, ни правила, прогон печатает и падает:
русское слово в английском кадре иначе всплывёт уже у инвестора.

**Английский заголовок длиннее русского при той же ширине колонки.** В `.cols--38` (слайд 3)
колонка 600 px держит примерно 17 знаков в строке `.h2`; более длинная фраза рассыпается на
пять рваных строк. Переносы в заголовках расставлены руками под эту ширину.

**После `bun run capture` сверьте слайд 9.** Демо-юзер создаётся заново на каждом прогоне, и
суммы у него другие. Скрипт печатает в конце три цифры дашборда — их надо перенести в блок
`.metrics`, иначе текст разойдётся с картинкой рядом. Нижняя навигация на снимках
телефона скрыта, на десктопе — нет: там тот же `<nav>` это боковое меню.

`public/shots/*.png` — исходники съёмки, `*.jpg` — то, что попадает в дек (PNG Chrome
укладывает в PDF несжатым растром, JPEG проходит как есть).
