# Компактный редизайн страницы «История»

**Дата:** 2026-07-27
**Файл:** `frontend/src/pages/history/HistoryPage.vue` (+ список транзакций)

## Задача

Страница истории — это гроссбух: её единственная работа — быстро найти операцию.
Сейчас интерфейс поиска занимает больше места, чем сами операции.

## Что не так сейчас (замер, iPhone 15, 393×852)

Вертикальный бюджет над первой транзакцией при открытых фильтрах:

| Блок | px |
|---|---|
| AppHeader | 57 |
| Обёртка `ImportInboxBanner` (`pt-4`, баннера обычно нет) | 16 |
| `pt-4` + вкладки типа | 52 |
| `pt-4` + поиск + `AccountSelector` + `CategoryChips` + `pb-2` | 214 |
| `pt-4` контента | 16 |
| **Итого** | **355** |

Плюс сам список расточителен: виртуализатор резервирует под строку 72 px, а строка
рисуется на 60 px — 12 px пустоты на каждую. Заголовок дня резервирует 44 px при
содержимом в 22 px. На экране помещается ~5,8 операций из 11 возможных.

Три отдельные проблемы UX, а не только плотность:

1. **Фильтры врут при поиске.** `useServerSearch` не принимает ни тип, ни счёт, ни
   категорию. Пока активен поиск, вкладки «Расходы/Доходы» видны и выглядят
   рабочими, но на выдачу не влияют.
2. **Состояние фильтров невидимо.** Когда блок свёрнут, единственный признак —
   точка 8×8 на иконке в шапке. Какой счёт, какая категория — не узнать не разворачивая.
3. **День теряется при прокрутке.** Заголовок дня с итогом уезжает вверх, и внутри
   длинного дня уже непонятно, что это за день и сколько он стоил.

## Направление

Список — герой страницы. Всё остальное сжимается до одной строки.

**Сигнатурный элемент — «линейка дня»**: заголовок дня с чистым итогом, который
липнет к верху при прокрутке внутри дня. Он не занимает дополнительной высоты
(замещает уехавший), даёт постоянный ответ на «какой это день и во сколько он мне
обошёлся» и превращает набор карточек в гроссбух. Это единственное место, где
редизайн позволяет себе смелость; всё остальное — тише, чем было.

## Решения

### 1. Одна строка управления вместо трёх блоков

```
┌──────────────────────────────────────────────┐
│ История                        [🔍] [⚙²] [⟳] │  AppHeader
├──────────────────────────────────────────────┤
│ [ Все · Расходы · Доходы · Переводы · Долги ] │  36 px
│ ⟨Карта ✕⟩ ⟨Продукты ✕⟩            Сбросить   │  26 px — только если фильтр задан
├──────────────────────────────────────────────┤
```

Поиск и фильтры — иконками в шапке, где пустовало место справа от заголовка.
Строке управления при этом достаётся вся ширина: на 393 px пять вкладок помещаются
ровно (353 px из 353 px), а с кнопками в той же строке пятая («Долги») обрезалась.

По нажатию на лупу строка морфится: вкладки уступают место полю поиска с кнопкой
«Отмена». Это не только компактнее — это честно: `useServerSearch` ходит на сервер
без фильтров, поэтому во время поиска тип-фильтр всё равно не применяется.

### 2. Счёт и категория — в шторку

`HistoryFiltersSheet` (vaul, как `AccountPickerSheet`/`CategoryPickerSheet` в
остальном приложении). Внутри — те же `AccountSelector` и `CategoryChips`, но с
`rows=3`: в шторке им просторно, а на странице они занимали 122 px постоянно.

Счётчик активных фильтров — на кнопке. Выбранные — чипами под строкой управления,
каждый снимается крестиком. Состояние фильтра видно, не открывая ничего.

### 3. Плотный сгруппированный список

- Строка: слот 72 → **60 px** (ровно по содержимому, пустоты больше нет);
  76 px для строк с тремя строчками в колонке суммы.
- Заголовок дня: 44 → **32 px**, липкий.
- Операции одного дня — **одна карточка** со скруглением сверху/снизу и волосяным
  разделителем по левому краю текста, вместо восьми отдельных карточек с зазорами.
  Это и плотнее, и читается как выписка, а не как лента.

### 4. Мелочи

- Обёртка баннера импорта скрывается через `empty:hidden`, когда баннера нет
  (было 16 px пустоты на каждом заходе).
- Пустое состояние компактнее: иконка 64 → 48, отступы `py-16` → `py-10`.

## Результат

Замерено в headless Chrome на демо-данных, 393×852 (без демо-баннера):

| | Было | Стало |
|---|---|---|
| Хром над списком, фильтры не заданы | 355 px | **113 px** |
| Хром над списком, фильтр задан | 355 px | **139 px** |
| Высота строки | 72 px (слот) / 60 px (содержимое) | 60 px |
| Высота заголовка дня | 44 px | 32 px |
| Операций на экране (852 px) | ~5,8 | **~11** |

Фактические высоты слотов после правки: `[32, 60, 60, 60, 60, 32]` — слот совпадает
с содержимым, пустоты не осталось.
