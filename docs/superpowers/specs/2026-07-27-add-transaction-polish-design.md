# «Новая транзакция»: юстированные чипы, сумма без карточки, плотный «Долг»

Дата: 2026-07-27
Страница: `frontend/src/pages/transactions/new/AddTransactionPage.vue` + `features/add-transaction/*` + `entities/category/ui/CategoryPicker.vue`

Третья итерация редизайна экрана. Предыдущие:
`2026-07-27-add-transaction-redesign-design.md` (сумма-герой, PR #101/#102) и
`2026-07-27-add-transaction-slab-redesign-design.md` (карточка счёта, PR #103).
Тот редизайн решил иерархию; этот убирает шаблонность оформления, чинит
рваную сетку чипов, делает вкладку «Долг» вдвое короче и снимает рывок на входе.

## Бриф

Пять запросов владельца продукта:

1. **Чипы категорий рваные** — по краям остаются пустые пространства, нужна
   другая формула распределения, желательно на всю ширину.
2. **Карточка суммы выглядит как ИИ-дизайн.**
3. **Кнопка сканирования чека непонятна** — иконка без подписи.
4. **Вкладка «Долг» выглядит плохо** — «Ещё» можно не заметить, часть мест
   занимает слишком много.
5. **Вход на страницу дёргается и лагает**, bounce-эффект не нравится.

Сценарий не меняется: **сумма → категория → «Добавить»** за 3–5 секунд.

## Разбор: что на экранах на самом деле

**Чипы на скриншоте — `CategoryPicker.vue`, не `CategoryChips.vue`.** Признак:
пунктирный чип «Ещё 4» с иконкой-сеткой (`apps`) рисует только Picker. Picker —
это `flex flex-wrap gap-1.5` с чипами по содержимому, отсюда рваный правый край.

`CategoryChips.vue` живёт в семи других местах (шторка фильтров истории,
модалки редактирования транзакции, частичного погашения, закрытия долгов, формы
подписки, quick-action, scan-receipt). Он **горизонтально скроллится**
(`w-max` + `overflow-x-auto`) и специально уезжает за край — «на всю ширину»
там противоречит замыслу. **В этой работе он не меняется.**

**Почему карточка читается как ИИ-дизайн.** Три шаблонных приёма подряд:
цветная полоска слева + сплошная тонировка подложки + micro-caps подпись с
трекингом. Это канонический «AI fintech card». Плюс на вкладке «Долг» карточка
вырождается в цветной прямоугольник с одним числом: счёт там выбирается ниже,
прогноза остатка нет — показывать нечего.

**Причины рывка на входе — две.**

1. **Автофокус суммы попадает в переход.** `useAmountInput` фокусит скрытый
   `input` в `onMounted` → мобильная клавиатура открывается посреди слайда →
   `h-dvh` пересчитывается → экран едет вместе с ней.
2. **Первая отрисовка формы тяжёлая.** В чанк страницы синхронно затянуты
   `Calendar` + `@internationalized/date` (`TransactionMetaRow`),
   `CategoryPickerSheet` на vaul (`CategoryPicker`) и весь `DebtPanel` с
   `PersonSelector`/`AccountSelector`/`ToggleRow` — хотя вкладка «Долг» почти
   всегда закрыта. Всё это парсится и монтируется в кадре, где стартует слайд.

**Отвергнутая третья причина: снятие нижней навигации.** Первоначальный диагноз
винил `MainLayout`: он прячет навбар через `v-if` по `route.name`, а
классический навбар — `shrink-0` **в потоке**, и его снятие увеличивает
контейнер, в котором обе страницы лежат `absolute inset-0`. Разбор этого не
подтвердил: смена роута, перерисовка `v-if` и старт `Transition` происходят в
одном flush'е Vue, то есть высота меняется **до** первого отрисованного кадра
слайда — входящая страница сразу размечается на итоговую высоту и посреди
перехода не прыгает. Отложенное снятие, которое казалось фиксом, наоборот
перенесло бы сдвиг на момент, когда экран уже стоит на месте (липкая кнопка
сабмита прыгала бы вниз через 260 мс после приезда), а на переходе между двумя
fullscreen-экранами возвращало бы навбар на время слайда. Правку откатили;
`MainLayout` остался прежним, кроме `@after-enter`.

**Пружин на экране две.** `UTabs` идёт по `duration-250 ease-out`, перелёта нет.
Перелёт `cubic-bezier(0.34, 1.56, 0.64, 1)` — у sliding-индикатора
`AccountSelector` (`entities/account`), а он на экране ровно один раз: чипы
счёта на вкладке «Долг». Вторая — `scale(1.03)` на первой набранной цифре
(`useAmountInput`, 160 мс); её же использует `HeroAmount` (вторая сумма
перевода, подтверждение импорта), поэтому снимается в двух местах.

## Решение 1: юстированные ряды чипов

### Формула

Чистая функция в новом модуле `shared/lib/layout/justifyRows.ts`:

```ts
packJustifiedRows(widths: number[], containerWidth: number, gap: number): number[][]
```

```
total    = Σwidths + gap * (n − 1)
rowCount = max(1, ceil(total / containerWidth))
target   = total / rowCount

жадный проход слева направо с lookahead:
  ряд закрывается, когда добавление следующего элемента
  перелетит target сильнее, чем недолёт от остановки на текущем
```

Возвращает индексы, сгруппированные по рядам. Ряды рендерятся как
`div.flex.gap-1.5`, каждый чип получает `flex: 1 1 auto; min-width: 0` — остаток
ряда добирается паддингом. Ряды сбалансированы, поэтому добор мелкий и
незаметный; названия не режутся.

### Откуда ширины

**`canvas.measureText`, а не замер DOM.** Ширина чипа =
`chrome + measureText(name, font)`.

`font` берётся из `getComputedStyle` контейнера (`fontWeight fontSize fontFamily`).

`chrome` — не хардкод, дублирующий CSS-классы, а чтение с живого чипа:
`paddingLeft + paddingRight + borderLeftWidth + borderRightWidth + columnGap` из
`getComputedStyle` первого чипа плюс `offsetWidth` его иконки. Все эти величины
**не зависят от `flex-grow`**: растягивается content-box, а паддинги, рамка,
зазор и иконка остаются теми же. Поэтому читать их можно с уже растянутого чипа
— второго прохода не возникает. Пока ни один чип не смонтирован, действуют
константы по умолчанию, соответствующие текущим классам.

Почему не DOM: замер в DOM требует двух проходов (натуральные ширины →
перегруппировка в ряды → ширины уже растянуты `flex-grow`), даёт мигание рваной
раскладки на первом кадре и риск петли «замер → перегруппировка → замер».
Погрешность `measureText` в пару пикселей **поглощается `flex-grow`**: она может
лишь сдвинуть точку разрыва ряда, но не оставить пустоту.

### Обёртка

`shared/lib/hooks/useJustifiedRows.ts`:

```ts
useJustifiedRows<T>(
  items: MaybeRefOrGetter<T[]>,
  labelOf: (item: T) => string,
  options: { gap: number; chrome: number },
): { containerRef: Ref<HTMLElement | null>; rows: ComputedRef<T[][]> }
```

Перезамер: `useResizeObserver` (VueUse) на контейнере + `document.fonts.ready`
однократно. Пока ширина контейнера неизвестна (SSR, скрытый контейнер) — один
ряд со всеми элементами; текущее `flex-wrap`-поведение как деградация.

### Применение

Только `entities/category/ui/CategoryPicker.vue`.

Чип «Ещё N» участвует в упаковке как обычный элемент: композабл дженерик по типу
элемента, а Picker передаёт объединённый список — категории плюс синтетический
элемент-заглушку для «Ещё». В шаблоне ряд рендерит либо чип категории, либо чип
«Ещё» по дискриминанту. Иначе последний ряд считался бы без «Ещё» и всё равно
не сходился по ширине.

## Решение 2: сумма без карточки

`features/add-transaction/ui/AmountCard.vue` → `AmountHeadline.vue`.

Уходят: рамка, `bg-card`, слой тонировки (`absolute inset-0 opacity-[0.07]`),
полоска слева (`absolute inset-y-0 left-0 w-1`) — **минус два
absolutely-positioned слоя**, — и собственные паддинги `px-4 py-4 pl-5`: блок
садится на общий отступ страницы `px-4`, и сумма выравнивается со всем
остальным содержимым.

```
←  Новая транзакция

●  Основной ⌄              точка 8px = цвет счёта; text-sm font-medium,
                           обычный регистр (не uppercase, без трекинга)
98 000  сўм                кегль ступенями по числу цифр, как сейчас
Останется 5 946 000 сўм
────────────────────────   волосяная линия вместо карточки
Расход │ Доход │ Перевод │ Долг
```

Цвет счёта остаётся информативным, но перестаёт заливать площадь: точка в
триггере плюс окраска каретки при фокусе. На вкладке «Долг» блок вырождается в
одну сумму — на голом фоне это нормально, полупустой коробки больше нет.

Список счетов из поповера уезжает в `entities/account/ui/AccountPopover.vue`
(триггер — слот, содержимое — счета с балансами). Его переиспользует «Долг», так
что разметка списка существует в одном месте.

## Решение 3: подписанная кнопка сканирования

Две подписанные половины в том же ряду — высота не растёт:

```
[ ⚇ Разделить расход        ]  [ ▤ Скан чека ]
      flex-1 min-w-0              shrink-0
```

Когда разделение настроено, левую половину занимает чип участников (аватары +
сводка) с `min-w-0` и обрезкой; правая остаётся подписанной.

## Решение 4: «Долг» — плотный список

```
┌──────────────────┬──────────────────┐
│    ↑  Дал        │    ↓  Взял       │   на всю ширину
└──────────────────┴──────────────────┘
┌────────────────────────────────────┐
│ ⚇  Кому дали в долг            ›  │
├────────────────────────────────────┤   один список, divide-y
│ ●  Основной                    ⌄  │   AccountPopover, не чипы
├────────────────────────────────────┤
│ ▦  27 июл.                     ⌄  │
└────────────────────────────────────┘
   Ещё · 1                        ⌄     волосяная линия сверху
   └ комиссия · срок · комментарий · тумблеры

Спишется 98 000 сўм с «Основного»       одна строка, text-xs
[         Создать долг          ]
```

Что уходит:

- **Четыре строки подписей** — уезжают внутрь строк иконкой и плейсхолдером.
- **Две рамки и два зазора** — человек, счёт и дата срастаются в один
  bordered-список с разделителями.
- **Инфо-блок** на две строки с `p-4` и заливкой → одна строка `text-xs` над
  кнопкой.
- **Комиссия** уезжает под «Ещё»: она необязательная, её подпись («Комиссия за
  перевод (необязательно)») была длиннее самого поля, и она зависит от
  `skip_transaction`, который тоже под «Ещё».
- **Чипы счёта** → строка списка с поповером. Побочный эффект: `AccountSelector`
  уходит с этого экрана. Сам компонент остаётся: он используется ещё в семи
  местах (редактирование транзакции, привязка Telegram-карт, форма подписки,
  закрытие долгов, quick-action, scan-receipt, фильтры истории).

«Ещё» получает волосяную линию сверху — сейчас это безликая текстовая строка,
которую не видно. `DebtDirectionPill` растягивается на всю ширину:
центрованная пилюля в ~160 px терялась.

Модель `useDebtForm` **не меняется** — переработка только в разметке `DebtPanel`.

## Решение 5: спокойный вход

| Причина | Правка |
|---|---|
| нужен сигнал «переход закончился» | `isPageTransitioning` рядом с `transitionName` в `app/router`: роутер ставит `true` в `beforeEach`, `MainLayout` снимает в `@after-enter`; в ветках без `Transition` (первая загрузка, popstate) роутер снимает сам. Плюс таймер-страховка на 600 мс — залипший флаг означал бы, что автофокус не сработает никогда |
| автофокус попадает в переход | `useAmountInput` вместо `onMounted` слушает геттер `autofocus` и фокусит один раз, когда тот станет `true`. Страница отдаёт `true`, когда `isPageTransitioning` стал `false`; на странице флаг-защёлка в одну сторону, иначе обратный переход выдернул бы хвост формы из уже уезжающего экрана |
| тяжёлые синхронные импорты | `defineAsyncComponent` на `Calendar` (в `TransactionMetaRow`), `CategoryPickerSheet` и `DebtPanel`. Чанк `DebtPanel` префетчим на idle после монтирования формы, чтобы первый заход на вкладку не ждал сети. `DebtPanel` остаётся под `KeepAlive` — async-обёртка объявляется на уровне модуля, чтобы ссылка на компонент была стабильной |
| слайд 350 мс | 260 мс на той же кривой `cubic-bezier(0.32, 0.72, 0, 1)`; только `slide-forward` и `slide-back`, `slide-tab-*` не трогаем |
| пружина суммы `scale(1.03)` | **удаляется целиком** вместе с `BOUNCE_MS`, `isBouncing` и `useTimeoutFn` в `useAmountInput`. Обратная связь остаётся: цифра появилась, кегль шагнул. Заодно минус мёртвый код |
| перелёт `AccountSelector` | `cubic-bezier(0.2, 0, 0, 1)` — торможение без возврата. Правка в самом shared-компоненте, поэтому достаётся и остальным семи его местам, хотя с «Долга» он и уходит: владелец указал именно на эту пружину |

**Отложенный хвост формы.** После перехода fade-in 120 мс получают
**мета-строка (комментарий/дата) и ряд «Разделить/Скан»**. Слайд везёт шапку,
сумму, табы, категории и кнопку сабмита: кнопка — главное действие, категория —
второй шаг сценария, появляться с задержкой они не должны. Отложенными остаются
ровно те узлы, которые тянут `Calendar` и vaul, — они в кадр слайда не попадают.

## Тесты

- `justifyRows.spec.ts` — пустой список; один элемент шире контейнера; набор,
  делящийся ровно; набор с длинным хвостом (проверка, что последний ряд не
  вырождается в один элемент); случай `rowCount === 1`; `gap` учтён в `total`.
- `CategoryPicker.spec.ts` — существующие кейсы плюс: чипы разложены по рядам и
  каждый получает `flex-grow`.
- `useAmountInput` — фокус приходит по смене `autofocus` с `false` на `true`;
  проверки на `isBouncing` снимаются вместе с полем.
- `DebtPanel` — комиссия рендерится только при раскрытом «Ещё».
- `useDebtForm.spec.ts`, `useTransactionForm.spec.ts`,
  `useSmartDefaults.spec.ts`, `useAmountSuggestions.spec.ts` — не меняются.

## Ожидаемый результат

- Ряды чипов заполнены по всей ширине, названия целы.
- Расход: минус ~28 px сверху (карточка → блок без рамки и паддингов).
- Долг: с ~8 ярусов до 4, ориентировочно вдвое короче.
- Вход: ни открытия клавиатуры, ни парсинга `Calendar`/vaul в кадре слайда;
  слайд 260 мс; пружин на экране нет.

**Замер после реализации** (Chrome DevTools, эмуляция 390×844, демо-данные):
ряды чипов — 4 шт., каждый заполняет 358 из 358 px ровно, ограничитель роста не
сработал ни разу. `Calendar` (11 КБ), `DebtPanel` (3,8 КБ) и
`CategoryPickerSheet` (2,2 КБ) выделились в собственные чанки и ушли из бандла
первой отрисовки; сторож бюджета — 236,0 из 250 КБ.
