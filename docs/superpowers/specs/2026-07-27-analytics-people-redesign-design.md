# Редизайн страниц «Аналитика» и «Люди» + оптимизация анимаций

**Дата:** 2026-07-27
**Ветка:** `feat/analytics-people-redesign`
**Статус:** дизайн утверждён, ожидает плана реализации

## Задача

Три независимые цели в одном PR:

1. **Аналитика** — страница громоздкая, занимает много места, часть содержимого не помещается по ширине.
2. **Люди** — страница морально устарела: плоский список имён без поиска, добавление через FAB → модалку.
3. **FPS/анимации** — убрать известные источники джанка на этих страницах и в разделяемом коде.

Пользователь выбрал направления: для аналитики — «плотный дашборд» (не вкладки-разделы, не косметическое ужатие); для людей — «контакты + долговое нетто» (не чистый менеджер контактов, не полноценный хаб человека).

Подтверждённые пользователем проблемы вёрстки аналитики: легенда доната, липкая шапка, горизонтальный скролл графика по дням, обрезающиеся суммы в карточках — все четыре.

### Горизонтальный скролл графика

`DailyExpenseChart.vue:51` считает ширину от константы:

```ts
const totalWidth = Math.max(count * (BAR_MIN_WIDTH + BAR_GAP), 280);
```

При 31 дне: `totalWidth = 310`, `barWidth = (310 − 62) / 31 = 8`, `chartWidth = 36 + 31 × 10 = 346` — против ~308px доступных внутри карточки. Отсюда `overflow-x-auto`.

Исправление: ширина столбца выводится из фактической ширины контейнера через `useElementSize` (VueUse). Скролл исчезает по построению, `overflow-x-auto` снимается. Для `scale=year` (12 месяцев) вопрос не стоял.

### Добавление без модалки

Одно поле сверху работает и фильтром, и вводом нового имени. Пользователь печатает «Дима»; если точного совпадения среди контактов нет — под полем появляется строка «＋ Добавить «Дима»», тап создаёт контакт оптимистично (`usePeople.createPerson` уже делает оптимистичную вставку).

Было: FAB → модалка → поле → палитра → «Добавить» (5 шагов). Стало: печать → тап (2 шага).

Цвет назначается детерминированно от имени — стабильная хеш-функция по `ENTITY_COLORS`, чтобы один и тот же человек всегда получал один цвет и повторное создание не «мигало». Существующий `getRandomEntityColor` для этого пути не используется.

FAB удаляется — он занимает угол экрана ради действия, которое теперь всегда доступно сверху.

### Компактный список

Строка 76px → 52px:
- `InitialAvatar size="md"` вместо `lg`;
- шеврон в круге 32px убирается — вся строка кликабельна, шеврон не нёс информации;
- освободившееся место справа занимает нетто по долгам.

Счётчик «Всего контактов: N» и суммарное нетто сливаются в одну строку-сводку.

Поиск показывается всегда, а не с порога в N контактов: он же служит полем добавления.

### Долговое нетто

Источник: `useDebts(userId)` — один плоский `GET /debts` без пагинации, плюс `useExchangeRates(currency)` для конвертации. Складывается по `person_name` тем же знаковым правилом, что и `foldGroupsIntoPeople`: `given` плюсом («вам должны»), `received` минусом («вы должны»); закрытые долги отбрасываются.

Сопоставление имени контакта с `person_name` долга — по `trim().toLowerCase()`. Долги хранят имя человека свободным текстом, а не `person_id`, поэтому точное совпадение строк — единственный доступный ключ; так же поступает вся остальная часть приложения.

Контакт без долгов показывается без суммы (не «0»).

Логика вынесена в `entities/person/lib/foldDebtsByPersonName.ts`, чтобы страница осталась тонкой и функцию можно было протестировать отдельно.

### Редактирование

Тап по строке → компактная vaul-шторка: поле имени, `UColorPicker`, кнопка «Удалить». Блок «Предпросмотр» (аватар `scale-[1.3]` в рамке на ≈150px) не переносится — аватар и так виден в строке списка, а цвет виден в самой палитре.

В шторке — строка-ссылка «2 долга · 240 000 →», ведущая на `/debts`. Это удерживает страницу в роли справочника контактов и не дублирует страницу долгов.

Свайпы `SwipeableItem` (влево — удалить, вправо — править) сохраняются. `ConfirmDeleteModal` для удаления сохраняется.

## Дизайн: FPS и анимации

Правки от самой весомой к самой мелкой.

1. **`backdrop-blur-md` на липкой панели аналитики** (`AnalyticsPage.vue:388`). Блюр пересчитывается каждый кадр скролла поверх меняющегося контента — самый дорогой пункт списка. Заменяется сплошным фоном.

2. **`transition: all`**:
   - `AnalyticsPage.vue` — слайд-переходы `slide-left` / `slide-right` (`transition: all 150ms`) → `transition: opacity 150ms, transform 150ms`;
   - **`shared/lib/transitions.ts`** — `listTransition` использует `transition-all` в трёх местах (`enterActiveClass`, `leaveActiveClass`, `moveClass`). Это разделяемый пресет: правка улучшает все списки приложения, не только эти две страницы.

3. **`DonutChart.vue`** (`:212`): в `transition` перечислен `filter`, который компонент никогда не анимирует — мёртвая запись, заставляющая браузер следить за свойством. `stroke-width` при выборе сегмента перерастеризует path каждый кадр. Подсветка выбранного сегмента переводится на `opacity`/`transform`.

4. **`IncomeExpenseBar.vue`** (`:20-49`): две независимые rAF-петли (`animatedIncome`, `animatedExpense`) пишут по своему рефу ~60 раз/сек → ~60 ререндеров компонента в секунду в течение 400мс. Заменяется на `shared/lib/hooks/useCountUp.ts` — один тикер на несколько значений, с уважением `prefers-reduced-motion` (через `usePreferredReducedMotion` из VueUse; сейчас он используется только в дашборде). Хук переезжает в новую `AnalyticsSummaryCard`.

5. **`content-visibility: auto`** + `contain-intrinsic-size` на секции «Динамика» и карточке темпа расходов — двух блоках, которые при первой отрисовке заведомо вне вьюпорта. На сводке и категориях не ставится: они видны сразу, и хинт только добавит работы.

6. **`transition-all` на строках списков** → `transition-colors`: строки списка людей (`PeopleListPage.vue:150`), строки легенды доната (`DonutChart.vue:177`).

7. **`will-change: transform`** на контейнере слайд-перехода периода — выставляется только на время перехода (через `*-enter-active` / `*-leave-active`), не постоянно.

8. **`onSwipeTouchMove`** (`AnalyticsPage.vue:309`) продолжает считать дельты после того, как определил жест как вертикальный. Ранний выход при `swipeIsHorizontal === false`.

9. **`DailyExpenseChart`** — привязка ширины к контейнеру (см. выше) попутно снимает layout-трэшинг от горизонтального скролла.

Проверка: performance trace через Chrome DevTools MCP до и после, а не на глаз.

## Риски

- **Шторка счетов снижает обнаружимость фильтра.** Смягчается бейджем с числом выбранных и окраской иконки в primary при активном фильтре.
- **Табы «По дням / Сравнение» прячут один график за тап.** Принято сознательно: одновременно они нужны редко, а выигрыш по высоте — весь второй виджет.
- **Нетто на странице людей — лишний запрос `GET /debts`.** Запрос кэшируется Vue Query и, как правило, уже прогрет со страницы долгов. Страница остаётся работоспособной, если запрос не удался: суммы просто не показываются.
- **Сопоставление контактов с долгами по имени, а не по id.** Ограничение схемы данных (в `debts` нет `person_id`), а не решение этого редизайна. Переименование контакта разорвёт связь с его долгами до следующего совпадения имён — то же поведение, что и на странице долгов сегодня.
