# Веб-версия приложения: отдельная десктопная отрисовка

**Дата:** 2026-07-31
**Статус:** утверждён, этап 1 в работе
**Область этапа 1:** фундамент + Главная + Счета + Новая операция

---

## 1. Задача

Приложение спроектировано под телефон. На широком экране оно работает, но выглядит как растянутый мобильник: колонка по центру, мёртвые поля по краям, шапки страниц спрятаны, а десктопные ветки написаны точечно и вне единой системы.

Нужна полноценная веб-версия пяти разделов сайдбара — **Главная, Аналитика, История, Долги, Профиль** — и всех страниц, к которым они ведут. Сценарии использования равнозначны все четыре: ввод пачками, анализ, обзор, точечные правки.

**Ключевое архитектурное требование заказчика:** мобильная и десктопная отрисовка разделены, чтобы шаблоны оставались читаемыми.

## 2. Что уже есть в коде

Разведка по пяти областям (дашборд, формы/шторки, master-detail, инфраструктура, дизайн-система) дала следующую картину.

### 2.1. Три несогласованных определения «десктопа»

| Определение | Порог | Где используется |
|---|---|---|
| `useIsDesktop()` (`shared/lib/composables/useIsDesktop.ts:8`) | 1024 px | 13 vaul-шторок, `MasterDetailLayout`, `AccountsPage`, `HistoryPage`, `DebtsListPage` — 11 мест |
| Tailwind `md:` | 768 px | `MainLayout.vue:71` (`SidebarNav` `hidden md:flex`), `:108`, `:118` (`BottomNav` `md:hidden`) |
| Локальный `useMediaQuery('(min-width: 768px)')` | 768 px | `DashboardStandardLayout.vue:6` |

**Мёртвая зона 768–1023 px:** сайдбар уже показан, `BottomNav` уже скрыт, но `useIsDesktop()` ещё `false` — вторая колонка не появляется, шторки остаются нижними, клик по счёту уводит на отдельный экран.

В `@theme` (`src/app/styles/index.css`) брейкпоинты не переопределены — действуют дефолты Tailwind v4 (md 768, lg 1024).

### 2.2. Десктопные ветки, написанные точечно

- **Дашборд.** `DashboardStandardLayout.vue` (12 строк) выбирает `DashboardStandardDesktop` (`grid-cols-12`, `col-span-8` контент + `col-span-4 sticky top-6` боковая панель) либо `DashboardStandardMobile`. **Оба варианта импортируются статически** — мобильный пользователь качает десктопную разметку. Шапки на десктопе нет вовсе: `DashboardMobileHeader` обёрнут в `md:hidden`. Ни одного `lg:`/`xl:` во всей области.
- **Master-detail.** `MasterDetailLayout.vue` (66 строк): `master` `flex-[5]`, разделитель `w-px`, `detail` `flex-[4]`, контейнер `mx-auto max-w-7xl`. Вторая колонка включается по `useIsDesktop()`. Emit `close` объявлен, но ни разу не вызывается изнутри компонента, хотя все три страницы на него подписаны.
- **Выбор элемента живёт в локальном `ref`, а не в URL** (`AccountsPage.vue:75`, `HistoryPage.vue:225`, `useDebtsPageState.ts`). Перезагрузка страницы и ссылка на выбранный счёт не работают.
- **Шторки.** 13 компонентов на `vaul-vue`, в каждом продублирован один и тот же ~40-строчный шаблон и тернарник `:direction="isDesktop ? 'right' : 'bottom'"` с классами `w-[420px] rounded-l-2xl`. Мобильные высоты разъехались: `70dvh` ×2, `80dvh` ×1, `85dvh` ×3, `90dvh` ×3, плюс `CategoryPickerSheet` с фиксированной `h-[85dvh]`.
- **`UModal`** (19 мест рендера) — всегда центрированный диалог с `max-h-[60vh]`. `DESIGN_SYSTEM.md:201-213` описывает у него мобильный bottom-sheet, которого в коде нет: **документация протухла**. Пять файлов с суффиксом `Sheet` на деле обычные `UModal`.

### 2.3. Ограничения, которые нельзя нарушить

- **Бюджет стартового бандла** — 250 КБ gzip (`scripts/check-eager-bundle.mjs`), текущий расход 236.4 КБ. Запас ~13.6 КБ. Barrel `shared/ui/index.ts` не tree-shakeable.
- **Оболочка `h-dvh` + `overflow-hidden`**, страницы внутри `Transition` лежат `absolute inset-0`. Страница обязана скроллиться внутри себя — «просто расти в высоту» она не может.
- **`VirtualGroupedTransactionList`** требует явной высоты через `calc()` и не берёт её от flex-родителя.
- **Демо-режим** меняет схему высот: `App.vue:114` и `MainLayout.vue:59` переключаются на `flex-1 min-h-0` ради `DemoBanner`.
- **vaul в jsdom роняет vitest** при закрытии шторки — нужен стаб `@/test/stubs/vaul`.
- **`pb-28`** (полоса под `BottomNav`) висит в 19 файлах, на десктопе это мёртвое место.
- **`prefetchPages()`** (`router/index.ts:78-118`) — жёстко зашитый список из 13 импортов мобильных страниц.
- **Тач-жесты не работают мышью:** `SwipeableItem` и `useSwipe` слушают только `touch*`-события; `PullToRefresh` — тоже чистый тач, кнопки «обновить» в приложении нет.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Уровень разделения | Отдельные desktop-страницы, общая логика в `model/`-слое |
| Граница | Одна: **1024 px** |
| Глубина «нативности» | Только панели и многоколоночность. Без Cmd+K, массовых действий, контекстных меню, drag-n-drop |
| Порядок работ | Фундамент → Главная (+ Счета, Новая операция) → остальные разделы отдельными спеками |
| Новая операция на десктопе | Модалка поверх фонового маршрута, URL меняется, прямая ссылка работает |
| Выбор в master-detail | Переезжает в URL (`?id=…`) |
| Компактный режим дашборда | На десктопе не поддерживается — это мобильная оптимизация |

**Следствие выбора границы, принятое осознанно:** на планшете в портрете (768–1023 px) вернётся `BottomNav` вместо сайдбара. Сейчас там сайдбар с мобильной разметкой страниц.

## 4. Архитектура

### 4.1. Слой платформы

```
src/shared/lib/platform/
  useIsDesktop.ts     — единственный источник правды, порог 1024
  platformPage.ts     — резолвер компонента по платформе
  index.ts            — точечный barrel (импорт только по подпути)
```

**`useIsDesktop`** переезжает из `shared/lib/composables/` в `shared/lib/platform/`. Причина переезда — не эстетика: сейчас это module-level синглтон, чей `useMediaQuery` создаётся при первом вызове **внутри `setup()` первого компонента** и цепляется к его effect-scope; когда тот компонент размонтируется, слушатель уходит вместе с ним. Новая версия создаёт `matchMedia` при инициализации приложения, вне scope, и экспортирует точку подмены для тестов.

Старый путь `shared/lib/composables/useIsDesktop.ts` реэкспортирует новый — 11 существующих мест не переписываются механически.

**`platformPage(mobile, desktop)`** — фабрика для роутера:

```ts
export function platformPage(mobile: AsyncLoader, desktop: AsyncLoader) {
  const Mobile = defineAsyncComponent(mobile);
  const Desktop = defineAsyncComponent(desktop);
  return defineComponent({
    name: 'PlatformPage',
    setup() {
      const isDesktop = useIsDesktop();
      return () => h(isDesktop.value ? Desktop : Mobile);
    },
  });
}
```

`defineAsyncComponent` грузит чанк при первом рендере — телефон никогда не качает десктопный вариант. Это прямо противоположно нынешнему `DashboardStandardLayout`, который импортирует обе ветки статически.

При пересечении 1024 px поддерево размонтируется. Данные переживают это в кэше Vue Query; теряется позиция скролла и локальное состояние формы. Принято.

### 4.2. Оболочка

`MainLayout` (129 строк) разделяется:

```
src/app/layouts/
  ui/MobileLayout.vue    — BottomNav (классический + liquid-glass), FULLSCREEN_FLOWS
  ui/DesktopLayout.vue   — SidebarNav, область контента, слой модальных маршрутов
  ui/AppShell.vue        — общее: skip-link, RouterView, Transition, демо-режим
  model/useLayoutData.ts — без изменений, вызывается только десктопом
```

Родительский роут вместо `MainLayout` получает `platformLayout(...)`. Сейчас оболочка монтирует **обе** навигации и прячет одну классом, из-за чего `SidebarNav` безусловно дёргает `useLayoutData` (профиль + счета + курсы валют) на телефоне. После разделения этих запросов на мобиле не будет.

### 4.3. Раскладка десктопной страницы

```
src/shared/ui/desktop-page/
  DesktopPage.vue     — шапка страницы + скроллируемая область контента
  DesktopColumns.vue  — сетка 12 колонок с именованными слотами
```

`DesktopPage` держит `h-full flex flex-col`, скролл — внутри области контента (`flex-1 overflow-y-auto`), ширина контента ограничена `max-w-[1440px]`. `pb-28` в десктопной ветке отсутствует по построению.

### 4.4. Оверлеи

```
src/shared/ui/overlay/
  UOverlay.vue        — mobile: bottom sheet (vaul); desktop: panel | dialog
  OverlayHeader.vue   — общая шапка (заголовок, крестик)
```

Проп `desktop: 'panel' | 'dialog'` (по умолчанию `panel`). Мобильная высота унифицируется на `max-h-[85dvh]`; `CategoryPickerSheet` с фиксированной `h-[85dvh]` приводится к общему правилу. `useDrawerKeyboard` (мутирует стиль в обход реактивности Vue, чтобы не терять фокус инпута) остаётся внутри `UOverlay` и применяется только в мобильном режиме.

На этапе 1 на `UOverlay` переводятся четыре шторки, задействованные Главной, Счетами и Новой операцией:

| Шторка | Через что попадает в этап 1 | Режим на десктопе |
|---|---|---|
| `entities/category/ui/CategoryPickerSheet.vue` | `CategoryPicker` в форме операции | `dialog` (внутри модалки формы) |
| `entities/account/ui/AccountPickerSheet.vue` | `AccountPopover` в форме операции | `dialog` |
| `entities/person/ui/PersonPickerSheet.vue` | `PersonPicker`, вкладка «Долг» | `dialog` |
| `features/split-expense/ui/SplitExpenseDrawer.vue` | `ExpensePanel` | `dialog` |

Оставшиеся девять мигрируют вместе со своими разделами — иначе этап 1 разрастается на 13 файлов сразу. Все четыре также используются `ImportConfirmPage` (942 строки, держит семь шторок одновременно) — её поведение после миграции проверяется отдельно, хотя сама страница в этап 1 не входит.

Режим `dialog`, а не `panel`: эти пикеры открываются **изнутри** модалки «Новой операции», и правая панель поверх центрального диалога читается как несвязанный слой.

`UModal` не трогаем: 19 мест рендера, и все они уже центрированные диалоги. Правим только `DESIGN_SYSTEM.md`, где он описан неверно.

### 4.5. Модальные маршруты

Для «Новой операции» на десктопе вводится `meta.desktopOverlay: true`.

`DesktopLayout` держит `backgroundRoute` — последний маршрут без этого флага. При переходе на маршрут-оверлей рисуется фон (компонент фонового маршрута) плюс `UOverlay` с содержимым. При прямом заходе по ссылке фоном становится Главная.

На мобиле флаг игнорируется — маршрут остаётся полноэкранным, как сейчас.

## 5. Страницы этапа 1

### 5.1. Главная

```
┌─ сайдбар 288 ──┬─ контент, max-w 1440 ───────────────────────────┐
│                │  Шапка: приветствие · период · «Настроить вид»  │
│                │ ┌── span 8 ────────────┐ ┌── span 4, sticky ──┐ │
│                │ │ Баланс: сумма слева, │ │ Быстрые действия   │ │
│                │ │ 3 метрики справа     │ │ Топ расходов       │ │
│                │ │ Счета — сетка 2×N    │ │ Бюджет             │ │
│                │ │ Последние операции   │ │ Долги              │ │
│                │ │ (12 строк)           │ │ Подписки           │ │
│                │ └──────────────────────┘ └────────────────────┘ │
└────────────────┴─────────────────────────────────────────────────┘
```

Состав и порядок виджетов берутся из профиля (`widgetOrder` / `hiddenWidgets`), деление на активность и боковую панель сохраняется (`ACTIVITY_WIDGET_IDS` / `SIDE_PANEL_WIDGET_IDS`).

Баланс на десктопе разворачивается в строку. Счета выкладываются сеткой. Последние операции показывают 12 строк вместо 5.

Общий model-слой уже существует и переиспользуется без изменений: `dashboardContext.ts` (InjectionKey на ~40 ключей), `useDashboardData`, `useDashboardQuickActions`, `useDashboardNavigation`. Из страницы в общий слой выносятся только мелочи: скролл-трекинг, feature-hints, флаги localStorage и четыре модалки.

Файлы `DashboardStandardLayout.vue`, `DashboardStandardDesktop.vue`, `DashboardSidePanel.vue` и `md:hidden`-ветки внутри `DashboardActivityColumn`/`DashboardMobileHeader` удаляются — их содержимое переезжает в desktop-страницу.

### 5.2. Счета

Список слева сеткой, детали справа. Выбор — в URL (`/accounts?id=…`), поэтому перезагрузка и прямая ссылка сохраняют выбранный счёт. Мобильный маршрут `/accounts/:id` остаётся отдельным экраном.

Формы (создание, редактирование, корректировка баланса) на десктопе — диалоги.

### 5.3. Новая операция

Модалка ~560 px по центру поверх фона. Внутри — та же `TransactionForm`, но десктопная обвязка:

- автофокус не ждёт конца слайд-перехода (в модалке его нет) — защёлка `isReady` по `isPageTransitioning` в десктопной ветке не используется;
- `SubmitBar` без `safe-area` и без компенсации `-mx-4 px-4`;
- скрытый input под нарисованной суммой сохраняется — но поверх него не должно оказаться drag-handle vaul (в режиме `dialog` его нет).

## 7. Тестирование

- **Существующие тесты остаются зелёными.** `DashboardPage.spec.ts` (752 строки) завязан на мобильную разметку — он продолжает проверять мобильную ветку, для чего `useIsDesktop` подменяется в `false`.
- **Новые тесты:** резолвер `platformPage` (какой компонент рендерится по обе стороны порога и что второй чанк не запрашивается), `useIsDesktop` (реакция на смену media query), десктопные страницы Главной и Счетов (состав блоков, порядок из профиля, выбор счёта в URL), «Новая операция» в режиме модалки.
- **Тесты со шторками** подключают стаб `@/test/stubs/vaul`.
- **Бюджет бандла:** `bun run check:bundle` после сборки — расход не должен вырасти (резолвер импортируется по подпути, десктопные чанки лениво).

## 8. Риски

| Риск | Митигация |
|---|---|
| Планшет 768–1023 теряет сайдбар | Осознанное следствие границы 1024; мобильная разметка там удобнее двух колонок по 370 px |
| Стартовый бандл упрётся в 250 КБ | `platformPage` ~20 строк, импорт по подпути; десктопные страницы только через `defineAsyncComponent`; проверка `check:bundle` в каждом PR |
| `prefetchPages()` качает чужие чанки | Список разводится по платформе |
| Направление слайд-перехода считается по `MAIN_NAV_ITEMS` (4 таба), а сайдбар — `DESKTOP_NAV_ITEMS` (5) | На десктопе переходы между разделами без слайда — `transitionName = 'fade'` или `'none'` |
| Развязка «Новой операции» с анимацией сломает автофокус на мобиле | Мобильная ветка не трогается; десктопная получает свою обвязку |
| `PullToRefresh` и `SwipeableItem` не работают мышью | На десктопных страницах они не используются; обновление — по инвалидации кэша и кнопке в шапке страницы |
