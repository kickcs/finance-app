# Чеклист-ревью: редизайн страницы подтверждения импорта

Дата: 2026-07-19
Статус: утверждён пользователем (вариант «Чеклист-ревью», охват — везде: TMA, PWA, десктоп)

## Проблема

`ImportConfirmPage` собран как форма создания транзакции (полный `TransactionForm` + карточка контекста + карточка действий). Суммарная высота ~800px не помещается во вьюпорт TMA (~650–740px). При этом задача экрана — **подтвердить уже распознанную операцию**: 90% полей предзаполнены, редактирование — исключение.

## Решение

Заменить форму на сводку-чеклист: крупная сумма + строки полей со значениями, редактирование по тапу через шторки. Целевая высота ~520px — один экран с запасом.

│      − 1 500 000 UZS           │   HeroAmount (тап = править)

  (ошибка валидации — строкой здесь)

## Секции

### 1. Структура страницы

Вертикальный flex на всю высоту (`h-full flex flex-col`): хедер → `flex-1 overflow-y-auto` контент → sticky-бар (`shrink-0`, `pb-safe`). Скролл — страховка, в норме всё видно. Десктоп: та же карточка по центру (`md:max-w-xl md:mx-auto`), sticky-бар внутри карточки обычным блоком.

### 2. Хиро-зона (одна карточка)

- Строка происхождения: `{merchant | 'Операция по карте' | 'Изменение баланса'} · {card_mask} · {relativeDate}` + метка «Из Telegram» (компактно, text-xs, primary).
- Сумма: переиспользуется **`HeroAmount`** как есть (инлайн-редактирование через скрытый input, выбор валюты, строка баланса/недостатка средств).
- Чип типа: `[Расход ▾]` — маленькая кнопка под суммой; тап открывает vaul-шторку с тремя опциями: Расход / Доход / Перевод (иконка + название, отметка активного). Выбор меняет `formData.type` через существующую логику (категория сбрасывается / TRANSFER, toAccountId обнуляется — как в `applyTypeChange`).
- `balance_change` с нераспознанной суммой: info-строка «Сумма не распознана — укажите её вручную» в хиро-зоне; для остальных balance_change — «Проверьте тип и сумму операции».

### 3. Чеклист полей

Карточка `rounded-2xl border divide-y`; каждая строка — компонент **`ReviewFieldRow`** (локальный, `pages/import-inbox/confirm/`): иконка (UIcon), лейбл, значение (или плейсхолдер «Выбрать»/«Добавить» tertiary-цветом), chevron_right. Высота ~48px (`px-3.5 py-3`).

Строки и их редакторы:

Для типов **расход/доход**:

| Строка | Редактор |
|---|---|
| Счёт | **`AccountPickerSheet`** — новая шторка в `entities/account/ui/`: список счетов (цвет-точка, имя, балансы), выбор закрывает шторку |
| Категория | существующий `CategoryPickerSheet` (pool по типу: expense/income) |
| Дата | существующий Popover + Calendar (как в TransactionForm) |
| Комментарий | **`CommentSheet`** — локальная шторка: UInput (автофокус) + хештег-подсказки через `useHashtagSuggestions` |

Для типа **«Перевод»** чеклист Счёт/Категория и HeroAmount хиро-зоны заменяются существующим **`TransferPanel`** целиком (у него свой HeroAmount, счета «Откуда/Куда», курс, комиссия, swap — пересобирать это строками дорого и рискованно ради редкого сценария). Строки Дата и Комментарий остаются под панелью. Экран перевода может быть выше одного вьюпорта — допустимо (редкий осознанный сценарий, скролл работает).

Состояние счёта/валюты/баланса для HeroAmount на странице — через существующий `usePanelState` (завязан только на `formData` + emit, вызывается со страничным адаптером).

Видимость строк по типу выносится в чистую функцию `reviewRows(type)` в `pages/import-inbox/model/` — покрывается vitest.

### 4. Ряд действий

Один ряд компактных чипов (как чипы категорий: `px-3 py-1.5 rounded-lg text-sm border`, иконка + текст) под чеклистом:

- **↩ Возврат долга** — виден при `eligibleGroups.length > 0 && !repaymentMatch`; открывает `DebtRepaymentSheet` (без изменений).
- **📎 Чек** — всегда; переход на scan-receipt с контекстом импорта (текущий `toScanReceipt`).
- **⑂ Разделить** — только type=expense; открывает существующий `SplitExpenseDrawer`. Настроенное разделение: чип становится активным «⑂ Разделено на N» (primary-подсветка) с крестиком сброса (`setSplitEnabled(false)`).

Баннер точного совпадения долга (`repaymentMatch`) остаётся без изменений — одна строка над чеклистом.

### 5. Sticky-бар

`[Отклонить]` (ghost, text-danger, фикс. ширина по контенту) + `[Подтвердить]` (primary, `flex-1`). Подпись «Подтвердить» едина для всех типов (вместо «Добавить расход/доход/Перевести») — на этом экране действие одно: подтвердить импорт. Ошибка валидации — text-xs text-danger над баром. `ConfirmDeleteModal` отклонения — без изменений. Блокировка на `isSubmitting || isClosing`.

### 6. Логика (не меняется)

Prefill по item, decideCategoryPrefill, retry-bookkeeping (`createdTransactionId`, `splitDebtsCreated`, `repaymentTransactionId`), `handleSubmit`, split-создание долгов с rollback, `repayGroup`, навигация `computeNext`/`goTo`, Telegram BackButton. Меняется только `<template>` и локальные UI-стейты (открытые шторки).

### 7. Удаляется / чистится

- Со страницы: `TransactionForm`, карточка quick-actions (2 больших ряда), зависимость от свайп-табов.
- Из `TransactionForm`: проп `hideDebtTab` (использовался только импортом); из `ExpensePanel`: проп `hideScanReceipt`. Параметр `typeOrder` в `useScrollableTabs` остаётся (общий механизм, покрыт тестами).
- `useTransactionForm`/`useSubmitTransaction`/`useSplitExpense` — используются страницей как раньше.

### 8. Ошибки и edge cases

- Нет счетов → строка «Счёт» с плейсхолдером, сабмит валидацией потребует счёт (текущее поведение «Выберите счёт для транзакции»).
- `suggested_account_id`/`suggested_category_id` — работают как сейчас (prefill).
- Клавиатура в TMA: шторки с инпутами (Комментарий) обязаны использовать `useDrawerKeyboard`.
- Смена типа на «Перевод» и обратно — категория/toAccount сбрасываются как в текущем `applyTypeChange` (логика повторяется в обработчике шторки типа).
- «⑂ Разделить» чип скрыт при type ≠ expense; настроенный split при смене типа с expense сбрасывается (как сейчас — split применяется только к расходу при сабмите; сброс делаем явным при смене типа).

### 9. Тестирование

- vitest: `reviewRows` (видимость строк по типу и валютам).
- Существующие тесты `debtRepayment.spec.ts`, `useScrollableTabs` — без изменений, должны остаться зелёными.
- `bun run build` (vue-tsc) + lint.
- Ручная проверка в TMA: помещаемость в один экран, шторки, клавиатура.
