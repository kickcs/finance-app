# Design Review: Выбор категории (CategoryChips) на странице добавления транзакции

**Review ID:** category-picker_20260713_233919
**Reviewed:** 2026-07-13 23:39

## Summary

Основная причина жалоб — **горизонтально скроллируемая многорядная сетка чипов**: при большом числе категорий контент уходит далеко вправо, его не видно и нет никакого аффорданса, что там что-то есть. Поиск спрятан за маленькой текстовой кнопкой, требует лишних тапов и не даёт быстрого выбора с клавиатуры. Сортировка категорий не адаптируется к реальному использованию (флаг `isFrequent` выставляется вручную в настройках, чем почти никто не пользуется).

## Critical Issues

### Issue 1: Горизонтальный скролл многорядной сетки скрывает категории

**Severity:** Critical
**Location:** `CategoryChips.vue:204-215` (`overflow-x-auto` + `w-max` + разбиение на `rows`)
**Category:** Usability

**Problem:**
Категории раскладываются в N рядов (4 для расходов) равной длины и растягиваются вширь (`w-max`). При 20+ категориях сетка становится в 2–3 раза шире экрана. Скроллбар скрыт (`no-scrollbar`), fade-градиента у правого края нет — пользователь не видит, что справа есть ещё категории, и не понимает, куда делась нужная.

**Impact:**
Это главный источник жалоб: «тяжело выбирать категории, если их много». Категории за краем экрана фактически невидимы; двумерное сканирование (вправо + по 4 рядам) когнитивно тяжелее обычного вертикального wrap-а.

**Recommendation:**
Отказаться от горизонтального скролла для полного списка. Два рабочих варианта (можно совместить):

1. **Inline-часть + полный пикер в bottom sheet.** Инлайн показывать только ~8–9 самых используемых чипов (2–3 ряда, `flex-wrap`, без скролла) + чип «Все категории». По тапу открывается bottom sheet (на desktop — modal) с поиском сверху (autofocus), секцией «Недавние» и вертикальной сеткой всех категорий. Так делают Money Lover, Zenmoney, CoinKeeper — паттерн знаком аудитории.
2. **Минимальный фикс:** заменить сетку на обычный `flex-wrap` по вертикали + collapse «Ещё N» (как сейчас, но раскрытие растёт вниз, а не вправо). Страница и так скроллится вертикально — это естественное направление.

## Major Issues

### Issue 2: Поиск спрятан и требует лишних действий

**Severity:** Major
**Location:** `CategoryChips.vue:171-195`
**Category:** Usability

**Problem:**
Поиск — маленькая текстовая кнопка «Поиск» (`text-xs`, ~44×24px) в углу заголовка. Нужно: заметить её → тапнуть → дождаться появления инпута → печатать. На мобильном тап-таргет меньше рекомендованных 44×44pt.

**Impact:**
Пользователи, у которых много категорий (именно те, кому поиск нужен), его не находят или считают неудобным — что и звучит в жалобах.

**Recommendation:**
- При количестве категорий выше порога (например, >12) показывать поле поиска сразу, без промежуточной кнопки — или как первый «чип-кнопку» с иконкой лупы в первом ряду.
- В варианте с bottom sheet — поиск закреплён сверху шита с autofocus.

### Issue 3: Результаты поиска нельзя выбрать с клавиатуры

**Severity:** Major
**Location:** `CategoryChips.vue:40-42` (обрабатывается только Escape)
**Category:** Usability

**Problem:**
После ввода запроса Enter ничего не делает — нужно тянуться пальцем/мышью к чипу. Нет подсветки первого совпадения, нет навигации стрелками.

**Impact:**
Ломается самый быстрый сценарий: «набрал 2–3 буквы → Enter». Особенно заметно на desktop и с открытой мобильной клавиатурой (кнопка «Готово»/Enter просто закрывает клавиатуру).

**Recommendation:**
Enter (и `enterkeyhint="done"`) выбирает первое совпадение; первое совпадение визуально подсвечено. Опционально — стрелки для перемещения по результатам.

### Issue 4: Поиск — точный `includes` без нормализации

**Severity:** Major
**Location:** `CategoryChips.vue:91`
**Category:** Usability

**Problem:**
`c.name.toLowerCase().includes(query)` — не находит при «е/ё» («Еда» vs «Ёда»), опечатках, не ищет по началам слов внутри составных названий с дефисами/слэшами.

**Impact:**
«Поиск не всегда выглядит удобным» — пользователь набирает запрос, не получает результат и считает поиск сломанным.

**Recommendation:**
Нормализация (`ё→е`, trim, схлопывание пробелов), матч по началу каждого слова с приоритетом (prefix-совпадения выше, `includes` ниже). Полноценный fuzzy (Fuse.js) не обязателен — на 20–50 элементах достаточно простой нормализации + ранжирования.

### Issue 5: Порядок категорий не отражает реальное использование

**Severity:** Major
**Location:** `CategoryChips.vue:65-99` + `pages/settings/categories` (ручной `is_frequent`)
**Category:** Usability

**Problem:**
Деление «частые/редкие» — ручной флажок в настройках. Внутри секций порядок фиксированный (порядок из БД). При этом в проекте уже есть `useSmartDefaults` (`features/add-transaction/model/useSmartDefaults.ts`), считающий частотность категорий по последним транзакциям — но он используется только для предвыбора одной категории.

**Impact:**
Нужная категория оказывается в конце горизонтального скролла или в свёрнутой секции «Ещё N», хотя пользователь выбирает её каждый день.

**Recommendation:**
Сортировать чипы (или секцию «Недавние» в bottom sheet) по частоте использования из тех же кэшированных транзакций, что уже читает `useSmartDefaults`. Ручной `isFrequent` оставить как override. Это самое дешёвое улучшение с самым заметным эффектом: топ-6–8 категорий пользователя всегда на первом экране.

## Minor Issues

### Issue 6: «Ещё N» раскрывает категории вширь, усугубляя Issue 1

**Severity:** Minor
**Location:** `CategoryChips.vue:93-95, 237-246`
**Category:** Usability

**Problem:**
Раскрытие infrequent-категорий добавляет их в те же ряды — сетка становится ещё шире, и «раскрытые» категории появляются за краем экрана, невидимо для пользователя.

**Recommendation:**
Решается вместе с Issue 1 (wrap вниз или bottom sheet).

### Issue 7: Нет ARIA-семантики группы выбора

**Severity:** Minor
**Location:** `CategoryChips.vue:217-234`
**Category:** Accessibility

**Problem:**
Чипы — просто `<button>` без `aria-pressed`/`role="radiogroup"`+`role="radio"`. Скринридер не сообщает, какая категория выбрана.

**Recommendation:**
`role="radiogroup"` на контейнер (с `aria-label="Категория"`), `role="radio"` + `aria-checked` на чипы.

### Issue 8: Пустой результат поиска — тупик

**Severity:** Minor
**Location:** `CategoryChips.vue:197-202`
**Category:** Usability

**Problem:**
«Ничего не найдено» — и всё. Нет действия «Создать категорию "<запрос>"», хотя пользователь только что явно сформулировал название.

**Recommendation:**
В пустом состоянии показать кнопку «Создать категорию "<query>"» (переход в manage-categories с префиллом или инлайн-создание).

## Suggestions

### Suggestion 1: Направления для bottom sheet пикера (если выбран вариант 1 из Issue 1)

- Секции: «Недавние» (последние 3–5 использованных) → «Все» вертикальной сеткой 4 колонки (иконка сверху, подпись снизу — компактнее и ровнее, чем чипы переменной ширины).
- Поиск закреплён сверху, autofocus при открытии на desktop; на мобильном — autofocus только по тапу на поле (чтобы клавиатура не съедала пол-экрана сразу).
- Кнопка «Управление категориями» внизу шита — сейчас до настройки категорий из формы транзакции не добраться.
- Haptics `trigger('selection')` при выборе — консистентно с остальным приложением.

## Positive Observations

- `useSmartDefaults` — уже готовая инфраструктура частотности для Issue 5.
